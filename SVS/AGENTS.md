# Запуск и отладка СВС

Как гонять Диспак на этом симуляторе и чем смотреть, что внутри происходит.
Про сами протоколы — `ПВВ.md` (канал ввода-вывода) и `МПД.md` (мультиплексор
и терминалы).

## Сборка

```sh
cd /home/leob/git/besm6/simh && make svs      # кладёт BIN/svs
```

## Прогон

**Пакетный.** Собирает рабочий образ диска, стирает барабан и запускает через
сторож размера трассы:

```sh
cd SVS && ./boot.sh                      # svs.ini, лимит 4 ГБ, таймаут 300 с
./boot.sh svs.ini 4 300                  # то же явно
SVS2053=/путь/svs2053.bin ./boot.sh      # другой дистрибутивный образ
KEEP_DISK=1 KEEP_DRUM=1 ./boot.sh        # не пересобирать образ и барабан
```

**Интерактивный.** То же, но на живом терминале — набранное с клавиатуры
приходит в машину слогом с линии 61, а выданное машиной печатается:

```sh
cd SVS && ./isvs.sh                      # int.ini, лимит 4 ГБ
```

В сеансе: **^E** уводит в `sim>` посреди прогона, `cont` возвращает в машину,
`do probe-mott.ini` ставит пробы.

**Голый сторож** — если нужен свой ini без сборки образа:

```sh
./runsim.sh [ini] [лимит-ГБ] [таймаут-с]
```

**Образ диска и барабан пересобираются перед каждым прогоном**, и это не
перестраховка: ОС пишет и на системный диск, и на барабан, так что повторный
запуск на грязных файлах невоспроизводим.

Дистрибутивный `svs2053.bin` как есть не загружается — два поля служебных слов
записаны в другом соглашении. Приводит их `tools/makeSVS2053.py`
(см. `ПВВ.md` §7Б.9); `boot.sh` и `isvs.sh` вызывают его сами.

## Трассировка

Полное описание — `Tracing.md`. Коротко: один ключ задаёт, **куда** идёт
трасса, другой — **что** трассируется, и нужны оба.

```
set console log=dispak.trace
set debug log                    трасса в тот же файл, что и вывод машины
set cpu0 debug=dev               только обмены каналов и устройств
set cpu0 debug=insn              покомандно, без регистров
set cpu0 debug                   всё, кроме fetch
set cpu0 nodebug
```

Разделитель разрядов — точка с запятой: `set cpu0 debug=insn;regs`.

**Окно по адресам — главный инструмент для долгих прогонов.** Покомандная
трасса пишет ~3 МБ/с и за 20 млн команд даёт под гигабайт; окно ограничивает
её диапазоном PC:

```
set cpu0 debug=insn
set cpu0 window=76000:77777      только МОТТ
set cpu0 nowindow
show cpu0 window
```

Окно действует на всё покомандное; строки `dev` и обращения к операндам
своего PC не имеют и печатаются всегда.

## Пробы

Точки останова с действиями; действие заканчивается `cont`, и прогон идёт
дальше:

```
break 77167;echof "--- ВЫДАЧС";e 76157;e M17;cont
break -w 76157;e PC;cont                 останов по записи
break -r <адрес>;e PC;cont               по чтению
```

Точки останова по чтению и записи срабатывают в любом режиме процессора,
приписка на них не влияет.

Готовый набор по МОТТ — `probe-mott.ini`, подключается из `sim>` командой
`do probe-mott.ini`. Опорные адреса модуля — `МПД.md` §7.

Ввод с консоли машине можно подать и в пакетном прогоне:

```
send after=100000000 delay=10000 "A\r"
```

## Регистры для `examine`

```
e CLOCK      часы 056, 44 разр., 1 мкс, циклический счётчик
e TIMER      таймер 057, 32 разр.; обнуление шлёт прерывание в разр.4 ГРВП
e M1 … e M17, e ACC, e RMR, e PC, e RPS0 … e RPS7, e RP0 … e RP7
```

## Ловушки

**`e <адрес>` читает ФИЗИЧЕСКУЮ память, мимо приписки.** К моменту, когда
загрузка доходит до ОС, `РПС3 = 0017 0042 0041 0040`: виртуальные страницы
12-14 (адреса 030000-035777, почти весь АДАП) отображены на физические 040-042.
Живые структуры АДАП-а лежат по **физ. 0100000 + смещение**, а по физ. 030000
остаётся брошенный исходный образ, который ОС затирает. То же и в низкой
памяти: часть адресов ОС отображена не на себя, и дизассемблировать их по
`e -m` не получится — надо сперва снять `RPS` и пересчитать адрес.

**Трассу держать в узде.** Незавершающийся `go` с покомандной трассой за
четверть часа вырастает до десятков гигабайт. Запускать только через
`runsim.sh`/`boot.sh`, пользоваться окном по PC, а `dispak.trace` удалять
сразу после разбора. Место на диске ограничено.

**Ввод с консоли идёт только с терминала.** `sim_poll_kbd()` отдаёт символы
при `sim_ttisatty()` либо когда они впрыснуты командой `send`. Под каналом
(`svs ... | cat`, перенаправление в файл) ввод до машины не доходит — отсюда
и `isvs.sh`, который потоки не перенаправляет.

**Слова 1-7 — тумблерные регистры пульта.** Программе они недоступны на
запись; значения туда кладёт `d 2 …` из ini через `cpu_deposit()`.
