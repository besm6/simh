# 8.2.3. Генерация архивной системы

*Раздел 8.2.3 инструкции по конфигурации ОС Диспак
(`besm6.github.io/wiki/os-config-instr.txt`, строки 1169–1337). Текст переведён
из машинного представления (заглавные буквы, смешанная латиница/кириллица) в
кириллицу обычного регистра; управляющие маркёры разметки убраны. Многоточие в
квадратных скобках `[…]` отмечает места, где исходник оборван.*

После вызова новой системы, до задания времени средствами ППО, необходимо
занести в ячейки 1 и 76003(8) информацию для вызова генератора архива:

- рр. 64-40 = 0;
- р. 39 = 1;
- рр. 38-23 = 0;
- рр. 22-17 — логический номер неоператорского терминала, с которого будет
  производиться генерация архива;
- рр. 16-1 = 0.

Затем следует набрать директиву «ВРЕМЯ» и убедиться в формировании архива.

После этого на операторский терминал будет выдано сообщение `АРХ:ТТ=ЛNТЕРМ`,
а на указанный терминал будет выдано приглашение «КЛЮЧ», в ответ на которое
необходимо указать ключ администратора архива. Если архив генерируется впервые,
то запрос ключа не производится.

Затем выдаётся приглашение «АРХ>». По директиве «СЕРВИС» произойдёт переход в
блок встроенного сервиса архива.

После этого пользователю выдаётся сообщение о версии программы сервиса архива
и запрашивается имя требуемой программы; в ответ необходимо задать имя «ГЕН».

Работа генератора может происходить в двух режимах: в режиме полной генерации,
когда значения всех основных параметров запрашиваются у пользователя
автоматически, и в режиме активности пользователя, когда пользователь сам
указывает имена параметров.

## 8.2.3.1. Определение параметров архива

### 8.2.3.1.1. Архивное пространство

Архиву требуются один или два постоянно стоящих диска: на одном из них
располагаются каталоги архива, на другом — их дубли (всякая запись информации в
каталог сопровождается записью и в его копию). В тех случаях, когда не
представляется возможным выделить архиву два постоянно стоящих диска, возможно
расположить и каталоги, и их копии на одном диске. В начальном состоянии
каталоги занимают 10(8) зон на каждом из дисков.

Оба диска должны быть заданы в генерации ОС как общие.

**Внимание!** Если архиву для каталогов выделяется только один диск, то при
генерации на вопросы «МД АРХ-» и «МД ДУБ-» задаётся один и тот же номер, а на
вопросы «L АРХ-» и «L ДУБ-» следует указывать полную длину этого диска.

После запроса томов для каталогов возможны вопросы: «ОТСУТСТВУЮТ […]».

Диагностика «НЕТ МЕСТА НА БУФЕРЕ РАБОТ» означает, что перед генерацией
необходимо освободить (на старой версии архива) 30(8) зон на основном диске
архива.

### 8.2.3.1.2. Общие шифры

В том случае, когда пользователь обращается к области, не указав её хозяина
(например, поставив в паспорте раздел «ЛЕНТ 30(ДУБНА)^»), область с таким
именем ищется среди его файлов и, если такого имени там нет, осуществляется
последовательный поиск этой области в «библиотеках» группы, отдела и в «общей
библиотеке». Так, если первые шесть цифр шифра задачи — «АААААА», то будет
выбрана первая существующая из областей «ДУБНА/АААААА», «ДУБНА/ААААХХ»,
«ДУБНА/ААУУУУ», «ДУБНА/ZZZZZZ», где «ХХ» — признак группы (рекомендуемое
значение — «..»), «УУУУ» — признак отдела (рекомендуемое значение — «0099»),
«ZZZZZZ» — общий шифр (рекомендуемое значение — «999999»). Сам шифр 9999
заводить (регистрировать ФИО в ОС) нельзя, хотя для других значений общего шифра
это разрешено.

### 8.2.3.1.3. Максимальная длина областей

Независимо от размеров свободного архивного пространства и бюджета, выделенного
пользователю, устанавливается предельный размер областей, которые могут
создаваться на данном вычислительном комплексе. Это ограничение недействительно
для администратора архива. Рекомендуется задавать значение этого параметра
возможно меньшим.

### 8.2.3.1.4. Наличие многомашинного комплекса

В тех случаях, когда архив работает на одной ЭВМ, служебные обмены
буферизуются, что позволяет существенно повысить скорость работы архивной
системы.

При генерации запрашиваются номера ЭВМ, для которых является общим архив. Затем
многократно производится запрос: «ЭВМ С ОБЩИМ […]». Указать список номеров ЭВМ,
имеющих общий буфер ввода-вывода (общий диск 2053).

### 8.2.3.1.5. Наличие бюджетной системы

Возможна работа архива без бюджетной системы; в этом случае все пользователи
пользуются неограниченными правами заведения областей (однако использование
этого режима не рекомендуется).

### 8.2.3.1.6. Интервал проверки целостности каталогов

В процессе выполнения ряда работ (таких, как создание и уничтожение областей и
т.п.) нарушается целостность каталогов архива. При этом в специально выделенной
зоне каталога сохраняется информация, необходимая для восстановления
непротиворечивости информации в случае сбоя ЭВМ. Однако проверка этой зоны
осуществляется только перед выполнением новой аналогичной работы, либо по
истечении заданного интервала.

Рекомендуемое значение параметра — 1-4 часа.

### 8.2.3.1.7. Интервал запуска вталкивания/выталкивания

У пользователя запрашивается, будут ли использоваться средства
вталкивания/выталкивания. При отрицательном ответе другие вопросы не задаются.

Все работы, связанные с вталкиванием/выталкиванием, запускаются автоматически
практически во всех необходимых случаях: при установке вторичного тома, при
обращении к вытолкнутой области и т.п. Однако, если машины, работающие с
архивом, имеют раздельные буфера ввода, то архив не получит события в том
случае, когда область, необходимая задаче, введённой на одной машине,
подкачана на другой ЭВМ. В этом случае проверка на вталкивание осуществляется
через заданные интервалы времени.

### 8.2.3.1.8. Интервал обслуживания вторичного тома

В случае использования вталкивания/выталкивания пользователю […]

Если к нерезидентной области в течение срока, заданного данным параметром
(в сутках), не было обращений, то область считается пригодной для выталкивания
на вторичный том. Рекомендуемое значение параметра — 5-10 суток.

Данный параметр, так же как и предыдущий, имеет значение в том случае, когда
архив работает на нескольких ЭВМ, имеющих раздельные буфера ввода. Параметр
определяет, с какой частотой будет осуществляться работа по
вталкиванию/выталкиванию со вторичным томом. Рекомендуемое значение — один час.

### 8.2.3.1.9. Срок хранения областей на первичном томе

Если к нерезидентной области в течение срока, заданного данным параметром
(в сутках), не было обращений, то область считается пригодной для выталкивания
на вторичный том. Рекомендуемое значение параметра — 5-10 суток.

### 8.2.3.1.10. Интервал проверки освобождения области от захвата

Если пользователь выдал экстракод безусловного захвата области (Э50 '115' или
его аналог), то архивная система проверяет, не захвачена ли эта область задачей,
работающей на другой ЭВМ. Если в каталогах архива имеется отметка о захвате
области другой машиной, то задача, выдавшая экстракод безусловного захвата,
закрывается до тех пор, пока область не освободится. Проверка освобождения
(повторное чтение каталогов) осуществляется через задаваемый интервал.
Рекомендуемое значение — 5 секунд.

### 8.2.3.1.11. Выбор тома для создания области

Имеется возможность запретить создание областей на неустановленных томах. Такой
запрет можно установить отдельно для каждого типа томов. У пользователя
запрашивается список групп, для которых допускается создание только на
установленных томах, — отдельно по видам «ДИСК» и «ЛЕНТ».

### 8.2.3.12. Группа для упрятывания

Для упрятывания задач по директиве оператора «УПР» операционная система создаёт
области архива. Эти области имеют нулевой вид, а их группа задаётся при
генерации архива.

### 8.2.3.13. Шкала групп для «бац»

Параметр задаёт шкалу групп, использование которых допускается при создании
областей буферизации выходного потока задачи (по разделу паспорта «БАЦ»).

### 8.2.3.14. Управляющие директивы

- «ВЫД» — обеспечивает выдачу параметров генерации архива.
- «ПЕЧ» — параллельная печать протокола работы.
- «ЗАП» — запись параметров генерации архива.
- «КНЦ» — окончание работы с генератором.

## 8.2.3.2. Генерация архива

Генерация архива начинается после выполнения действий, предписанных пунктом
8.2.3.

Параметры генерации архива хранятся в зоне 751 системного диска; после
генерации необходимо обеспечить дублирование этой зоны на дубли системных
пакетов. Если ЭВМ многомашинного комплекса работают с разными системными
пакетами, то генерацию следует проводить на каждой из ЭВМ комплекса.

Для того, чтобы осуществить роспись каталогов архива, необходимо на 1-м
тумблерном регистре задать в 16-1 разрядах двоично-десятичный номер МД архива
(в противном случае программа завершится с диагностикой «НЕТ КЛЮЧА РОСПИСИ
КАТАЛОГОВ!»). Номера разрядов приведены в представлении БЭСМ-6.

При росписи каталогов архива тома МДАРХ и МДДУБ заносятся в состав архива как
тома 0-й группы вида «Д».
