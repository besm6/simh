# Интерфейс МПД в МОТТ: листинг dispak-svs и сборка тома 2153

Сравниваются:

* **A** — `besm6.github.io/sources/dispak-svs/мотт.bemsh` (2246 строк), листинг;
* **B** — `re-dispsvs/src/mott.bemsh` (1996 строк), тот же текст, доведённый до
  совпадения с двоичным МОТТ на томе 2153. Строчные буквы в B — команды,
  восстановленные по двоичному коду, с абсолютными адресами (`'3325'`,
  `'74540'`) вместо имён.

Разбор по исходным текстам, на симуляторе не проверялся.

## Общее ядро (одинаково в A и B)

* Разбор прерывания МПД: `ПРПРОЦ` проверяет `РЕГ '252'` по `ЕВМПД`/`ЕПРМПД`
  (`мотт:97-106`).
* Приём слога `ПСЛ`: два байта из `РЕГ '253'`/`'252'`, строб `РЕГ '50'`, затем
  `ПАСМПД` (`мотт:548-580`, `mott:306-345`).
* Обработка сообщений `СООБАС`, `ТАС`, `ШЗПРИМ`, признаки ошибок в `ТСЛ`,
  статистика `КЧС1`.
* Выдача слога `ВЫДАЧС`, `ПСЛОГ`/`ТРУБА`, секретный приём `ТАЙНА` → `Е5`
  (`мотт:1528-1543`).
* Маска выдачи `УМВМПД`: `РЕГ '254'` ИЛИ `ЕВМПД`, запись `ВРЕМПД`.
* Сохранение регистров: в обоих М11/М12. В B написано `СЧИ М13`, но листинг
  печатает номера регистров восьмерично: `mott.lst:335` кодирует `042 0013`,
  то есть регистр 11 — тот же, что восстанавливает `УИА (11)` в `ВЫХОД`.

## Только в сборке 2153 (B)

1. **Второй путь приёма из МПД** (`mott:254-305`), под меткой `ПРМПД`:
   * слог читается из `рег '254'`, опрашиваются разряды `Е17`/`Е18`
     `рег '255'`;
   * пишется `рег '115'`, используются ячейки `'3325'`/`'3326'`;
   * линия проверяется по `ГРВ` и таблице `'3070'`, при плохой линии —
     `стоп 1`;
   * ставится признак `D77613`; пока он стоит, `ВЫХОД` снова опрашивает
     прерывания через `ПРПРО3` (`mott:983-984`).

   Обычный разбор прерывания обходит этот блок и идёт на `G76247`
   (`mott:110`, «было ПРМПД»); ни одна команда файла не переходит на `ПРМПД`.
   Блок начинается с `по '56605'`, то есть в него входят по абсолютному адресу
   откуда-то ещё, с уже выставленным ω. Вызывающий не найден.
2. **Запуск выдачи через тот же интерфейс** (`mott:778-799`):
   * для линии МПД при `D77614 ≠ 0` вместо маски `ЕВМПД` — импульс
     `рег '246'/'46'` (разряд `Е2`), `'3325' := '3326' | Д`, запись
     `рег '115'`;
   * при `D77614 = 0` — переход на `УМВМПД`, как в A;
   * `ШАС01` ставится для любой линии и снимается на остальных ветвях;
     в A — только для линий МПД (`мотт:1027-1029`).

   Предположение (из кода не следует прямо): пункты 1 и 2 — драйвер другой,
   более новой модели МПД/КВУ.
3. **Буфер трассы** `D76731`/`D76732`/`D76733` (`mott:1010-1012`): последние
   8 событий по одной выбранной линии (`D76731`) — входящие сообщения в
   `СООБАС` (`mott:999-1013`) и исходящие слоги в `ВЫДАЧС`, помеченные `Е48`
   и записываемые, только если в слоге стоит разр.16 (`mott:1324-1337`).
   Похоже на отладочную заплату.
4. **`МАССВС`** = `М32В'700'` вместо `М32В'1700'` (`mott:122`): разр.42
   `РЕГ '252'` больше не считается прерыванием от СВС. B проверяет `Е42`
   отдельно в начале (`mott:101-102`); что делает с ним восстановленная
   команда `ЗП ,`, по тексту не видно.
5. **Запуск выдачи на ЕС-7920**: та же логика `ПБ ВШГ`, но ячейка
   `'74540'` и константа `Д` вместо `ВЫДТЕС`/`ЕВТЕС` из `АСПВВ`
   (`мотт:1022-1026` против `mott:812-821`).

## Только в листинге dispak-svs (A)

1. **Запрос состояния линии («ЗСЛ»)**:
   * перед выдачей `ВЫДМПД` может послать слог запроса состояния линии
     (`R := Е8`) и отметить линию в `ШКЗСЛ` (`мотт:1477-1493`);
   * ответ проверяется в `ПРОЛИН` по `КВЗСЛ = В'157'` («ЧК,ПП,ПНП,N ЭВМ»,
     `мотт:1396-1412`, `1863`); если линия не встала на выдачу, её
     устанавливают ещё раз;
   * включается разр.31 слова 6: `СЧ 6 / И Е31 / ПО ВАС3Б "РАБОТАЕМ БЕЗ 'ЗСЛ'"`.
2. **Условие `ЕСЛВ` в `ВАС3С`**: «служебную выдачу закончим только при '000'»
   (`мотт:1574-1576`); в B на его месте `ноп`.
3. **`КЧС`, «ПРЕКРАЩАЕМ РАБОТУ С МПД»** (`мотт:1377-1393`): ставит `ЕЧПМПД`,
   вызывает НЕРОТ, перезапускает выдачу. Единственный вход — `КЧС2`
   (`мотт:2137-2140`), которого никто не вызывает и не экспортирует: мёртвый
   код. Его отсутствие в B поведения не меняет.

## Для симулятора

`svs_mpd.c` моделирует интерфейс A: регистры `252`/`253`/`254`/`256`/`50`/
`52`/`53` и служебные слоги `0xbd01`/`0xbd11`. Если системный диск грузит МОТТ
сборки 2153 и `D77614` взведён, ОС будет работать и через `255`/`115`/`246`,
которых симулятор не знает.

Какую версию МОТТ грузит `svs2053-fixed.bin`, не проверено. Проверка: сравнить
память с 076000 со словами из `re-dispsvs/build/mott.lst`, например по адресу
`76061` (переход `ПЕ G76247`) и `76247` (метка `G76247`).
